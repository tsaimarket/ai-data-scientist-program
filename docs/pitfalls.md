# 不會報錯，但結論全錯的坑

這份清單只收一種東西：**程式跑得出數字、不丟任何例外，但結論是反的**。
編譯錯誤會自己現形，這類不會——它會安安靜靜地讓你把錯的結果寫進報告。

> 🚧 本頁施工中：四個坑的說明已列出，**可執行的最小重現腳本待補**。

## 1. `confusion_matrix` 的左上角是 TN，不是 TP

scikit-learn 的排列是 `[[TN, FP], [FN, TP]]`。直覺上會以為左上角是 TP，
於是把 TN 當成 TP 去算 precision／recall，數字照樣算得出來，方向全錯。

## 2. `precision_score` 的 `zero_division` 決定 0/0 要回 0 還是 1

當模型一個正例都沒預測出來時，precision 的分母是 0。
`zero_division=0` 會回報 0（看起來很糟），`zero_division=1` 會回報 1（看起來完美）。
同一個廢模型，兩種設定給出兩個相反的評價。

## 3. Blending 混進沒調參的模型會讓整體變差

集成學習不是「加越多模型越好」。實測把一個未調參的弱模型加進 blending，
整體表現會倒退——但程式不會抱怨，你只會看到分數莫名其妙掉了一點。

## 4. DBSCAN 的雜訊標籤是 `-1`，不是 0

`0` 是合法的第一個群編號。如果照「雜訊 = 0」去過濾，結果是
**把整個第一群刪掉、把所有雜訊留下來**——資料量看起來還很正常，但已經完全錯了。
