# EDA 探索性資料分析（M5）

> 定位：清洗（M2–M4）之後、建模之前的那一段。**目的不是做出漂亮的圖，是縮小特徵集、生出可檢驗的假設。**

## 一、EDA 在做的三件事

| | 做什麼 |
|---|---|
| **發現模式** discover pattern | 看出「這欄跟目標有關係」 |
| **檢驗假設** test hypothesis | 用統計方法驗證那個關係是不是真的 |
| **檢查假設** check assumption | 確認建模方法的前提成立（常態？獨立？線性？） |

🕳️ 只做第一件＝看圖說故事。⭐ **後兩件才是把「看起來有關」變成「可以拿去建模」的關卡**——呼應 `principle-相关不等于因果建关系图谱`。

## 二、循環流程（不是一次性步驟）

```
蒐集並清理資料
    ↓
以視覺化快速篩選特徵
    ↓
得到據以建模的一套特徵值
    ↓
建模完成
    ↓
模型預測 vs 實際情況比較
    ↓
持續優化 ──────┘ 回到上面任一步
```

放進全流程來看：

```
原始資料 → 清洗 → EDA → 建模 → 報表/產品 → 真實世界驗證 → 回饋更多資料 → （回到清洗）
```

⭐ **「真實世界驗證 → 回饋更多資料」這一段才是 KDD 跟一次性分析的分野**——見 [concept-資料探勘與kdd流程](concept-資料探勘與kdd流程.md)。

## 三、四張標配圖（課堂以房價資料集示範）

| # | 圖 | 看什麼 |
|---|---|---|
| 1 | **目標變數分布圖**（直方圖） | 房價典型是**左陡右緩的偏態**→ 提醒要不要取 log 轉換 |
| 2 | **各特徵的直方圖** | 一次掃完 80+ 欄，找「值全擠在一起」的死欄 |
| 3 | **特徵關聯矩陣圖**（heatmap） | 兩件事一起看：誰跟目標相關 ＋ **誰跟誰彼此相關** |
| 4 | **類別型特徵 × 目標的盒鬚圖**（Box Plot） | 類別欄沒有相關係數可算，只能靠 box plot 比組間差異 |

選圖的判準另見 `framework-基本統計圖選型`（條形＝數量／餅＝總分／折線＝序列）與 `framework-資料視覺化選圖`。

## 四、⭐ 特徵篩選的三條門檻

| 門檻 | 條件 | 為什麼 |
|---|---|---|
| **留分布範圍廣的** | 值有變化 | 沒變化的欄對模型沒有資訊量 |
| **剔除缺失過多** | **None 超過 30%** | 補起來的成分比真值還多 |
| **剔除數值過度集中** | 幾乎全趨近於 0／單一值 | 同上，等於常數欄 |
| **共線性擇一** | 兩個高相關特徵**彼此也高相關**（課堂例：`YearBuilt` × `GarageYrBlt` ＝ **0.83**）→ 刪其一 | 留兩個不會更準，只會讓係數不可解讀 |

⚠️ **30% 是經驗值不是定律**——缺失本身可能就是訊息（沒有車庫 → 車庫年份必為 None）。刪之前套 M4 的原則：先問「為什麼會缺」，見 [framework-離群值與資料轉換](framework-離群值與資料轉換.md)。

⭐ 共線性的處理選項不只「刪一個」，還有降維／特徵組合，選型看 `framework-预处理选型决策表`。

## 實作

- 範例 notebook：`detailed-exploratory-data-analysis-with-python.ipynb`，資料 `train.csv`（Kaggle 房價，80+ 特徵）
- 主要套件：**Pandas ＋ Seaborn**（`df.corr()` → `sns.heatmap()` → `sns.boxplot()`）

## 對接

- ⚠️ EDA 看出的「上線後留存變高」是**相關**不是因果 → 仍受 A/B 必須並行的鐵律約束（`principle-时间序列不适合复杂商业环境`）。
