# 關聯分析與購物籃分析（M6）

> 在交易／關係資料中找出**項目之間的頻繁模式**：「某些屬性同時出現」的規律。典型應用＝**購物籃分析**（Market Basket Analysis）。
> ⚠️ 講義原文用「因果結構」形容關聯分析找到的東西——**那是措辭寬鬆，關聯規則給的是共現不是因果**，見下方失敗模式。

## 一、⭐ 三個指標（規則 X → Y）

| 指標 | 是什麼 | 直覺 | 門檻（課堂建議） |
|---|---|---|---|
| **Support** 支持度 | X 與 Y **同時出現**的比例 | 這組合夠不夠常見？ | 實作起手 **min_support ≈ 0.07**；≥ **0.3** 算很值得關注 |
| **Confidence** 信賴度 | 買了 X 的人**也買 Y** 的條件機率 P(Y\|X) | 規則準不準？ | **> 0.5**，嚴一點 **> 0.8** |
| **Lift** 提升度 | 「一起買」vs「各自獨立買」的比值 | ⭐ 這個組合**有沒有加強效果** | **> 1** 才有意義；要挑強規則設 **> 4 或 > 6** |

⭐ **只有 Lift 是拿來判斷「有沒有效」的**：
- `Lift = 1` → X、Y 互相獨立，同時出現純粹因為兩個都熱賣
- `Lift > 1` → 有正向加強（可拿去做搭售／推薦）
- `Lift < 1` → 互斥（買 X 的人反而不買 Y）

🕳️ **失敗模式＝只看 Support/Confidence 就下架／搭售**。熱門商品（如塑膠袋、基本款）會跟任何東西同時出現，Support 與 Confidence 都漂亮但 Lift ≈ 1 ＝ **沒有任何資訊**。這正是 `framework-如何选分析算法` 的「頻繁規則≠有效規則」。

⚠️ 再往下一層：Lift 高也只是**共現強**，不代表「因為買 X 所以買 Y」——可能是第三個因素（同一檔促銷、同一個購物情境）造成。見 `principle-相关不等于因果建关系图谱`、`principle-相關性不等於因果性`。

## 二、經典案例

| 案例 | 內容 |
|---|---|
| **啤酒與尿布** | 約 **67%** 同時購買，關聯分析的教科書案例 → `case-啤酒尿布`（⭐ 該筆記的重點：**價值不在發現關聯，而在同一發現可導出便利／促銷／動線三種不同策略**） |
| **課堂德國案例** | 跑 Online Retail 資料集、篩出德國顧客後，發現**森林動物圖案的絆創膏（OK繃）相關商品**被頻繁一起購買 ⭐ 重點是「**先切分群再跑規則**」——全體資料跑出來的規則往往被主力市場淹沒 |

## 三、兩個演算法

| | **Apriori（先驗）** | **FP-growth** |
|---|---|---|
| 思路 | **由下而上逐層搜尋**：先找頻繁 1-項集 L1 → L2 → L3…直到找不到 | 把頻繁項目**按支持度降序壓縮存進 FP-Tree**，之後直接在樹上遞迴找 |
| 關鍵性質 | ⭐ **一個頻繁項集的任一子集也必為頻繁項集**（反過來用：子集不頻繁 → 超集直接剪掉，大幅縮小搜尋空間） | 過程中**不產生候選項集** |
| 掃描資料庫 | **多次**（每一層掃一次） | ⭐ **只要兩次** |
| 缺點／優點 | ❌ 佔用空間大、運算成本高 | ✅ 執行效率明顯優於 Apriori |

⭐ 一句話：**Apriori 好懂（面試會問那條先驗性質），FP-growth 好跑（資料量大時用它）**。

Apriori 逐層剪枝的示意（min_support = 3）：算完 1-項集留下頻繁的 → 只用這些組出 2-項集 → 不夠頻繁的（如 `{1,3}` support=1）當場淘汰，其超集不必再算。

## 四、實作：購物籃分析

### ⭐ ETL 前處理是必要步驟（不是可選）

原始交易明細是**長表**（一列一筆商品），演算法要的是**寬表**（一列一張訂單、一欄一種商品）：

```
InvoiceNo | Item      →     InvoiceNo | 商品A | 商品B | 商品C
   1001   | 商品A            1001     |  1    |  1    |  0
   1001   | 商品B            1002     |  0    |  1    |  1
   1002   | 商品B
```

步驟：`group by 訂單編號` → 轉置（pivot／`unstack`）→ 數量欄轉成 0/1（有買/沒買）。
用到的是 M4 的合併與重塑，見 [framework-離群值與資料轉換](framework-離群值與資料轉換.md)。

### 執行順序

1. 洗資料（去空白、退貨單 `InvoiceNo` 開頭 C 要剔除）
2. 依市場／客群**切分子集**（如只留德國）
3. 轉寬表 → 0/1 編碼
4. `apriori(df, min_support=0.07, use_colnames=True)`
5. `association_rules(..., metric="lift", min_threshold=1)` → 再用 `lift > 4` ＆ `confidence > 0.5` 篩
6. **人看規則**：哪幾條是廢話（本來就同一系列）、哪幾條真的可以拿去做搭售

參考實作：`pbpython.com/market-basket-analysis.html`（`mlxtend` 套件）
